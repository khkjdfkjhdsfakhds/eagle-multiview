# MultiView TXT 后台保存

此配套服务用于 Eagle MultiView 正式版，使用 Eagle 官方 `eagle.item.getById()` 与 `Item.replaceFile()`，不打开或选中素材、不主动显示窗口。不是通用网络执行工具，也不会扫描或修改未提交为保存目标的素材。

## 启用

1. 在 Eagle 插件管理界面中，通过当前版本提供的本地开发插件加载入口，选择本文件所在目录（其中包含 `manifest.json`）。需由 Eagle 确认加载并启用后台服务。
2. 启动 Eagle MultiView。服务通过正式版自身数据目录中的私有连接文件连接本机回环端口；不要求输入密钥，不监听局域网。
3. 只在专用测试库中首次验证 TXT 输入、保存与前台保持，确认后再用于用户明确编辑的素材。

构建版随 App 附带完整目录，位于应用包 `Contents/Resources/Eagle TXT Save Plugin`。不要只复制一个 JS 文件或手工修改 Eagle 资料库。

## 行为与边界

- 只接受指定库、指定 TXT ID、匹配预期内容版本且位于 MultiView 暂存目录的候选文件。单份最大 5 MB。
- 不以 SDK 的 `undefined` 返回值判失败；写后比较正文哈希，缩略图延迟单独反馈。
- 结果不确定时先做只读核验；不会重新执行原保存请求。真实未完成的替换保持门禁，避免后到写覆盖前到内容。
- 零字节正文按当前 Eagle SDK 限制保留为草稿，不偷偷补字符或改成直接写库。
- 插件依赖 Eagle 运行；退出或停用后 MultiView 仍保留草稿。无需给服务配置任意文件路径或网络地址。
- 草稿、暂存、版本备份、鉴权文件均位于正式版独立数据目录 `eagle-multiview`；Review 配套插件仍只连接旧 Review，互不代收保存任务。

本说明描述实现与启用要求，不代替交付报告中的真实 Eagle/焦点验收记录。由 Review 转到正式版时，需要启用本目录的新正式版插件；旧 Review 插件不代替此插件。
